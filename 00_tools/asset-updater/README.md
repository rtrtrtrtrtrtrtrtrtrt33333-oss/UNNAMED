# Обновление файлов персонажей

Запуск: двойной щелчок по `start.bat`. Нужен Python 3.9+ с Tkinter
(в текущем окружении установлен). Для конвертации нужен Pillow, уже установленный
локально в `_vendor`. На другом компьютере из корня проекта:
`python -m pip install --target 00_tools/asset-updater/_vendor -r 00_tools/asset-updater/requirements.txt`.

1. Выбери проект и персонажей. Ctrl/Shift позволяют выделить несколько строк.
2. Выбери назначение: фон страницы, фон плейлиста, палитра, шрифты или свой путь внутри `assets`.
3. Выбери исходный файл и нажми «Показать замены».
4. Проверь список и нажми «Применить».

Каждый персонаж сохраняет собственную копию файла. Сайт не зависит от этого
инструмента. CSS копируется целиком, без объединения отдельных переменных.
Статичные JPG/JPEG, WebP, BMP и другие поддерживаемые Pillow изображения
конвертируются в настоящий PNG перед заменой. Размеры и прозрачность сохраняются,
ориентация EXIF учитывается. Исходник не меняется. Анимация и многостраничные файлы
отклоняются, чтобы не потерять кадры. Пустые и повреждённые изображения не принимаются.
Это не миграция всех изображений сайта: обновляются только выбранные PNG-назначения.

Исключение для анимации: «Фон плейлиста (GIF)» заменяет
`assets/images/06_playlist-background.gif` настоящим GIF. Все кадры проверяются,
затем исходные байты копируются без перекодирования: скорость, повтор и прозрачность
сохраняются. Другие GIF можно заменить через свой путь внутри assets.
Для PNG-назначений анимированные файлы по-прежнему отклоняются.

Отсутствующие файлы пропускаются — инструмент не создаёт пути, которые страница
может не использовать. Одинаковые файлы тоже пропускаются. Ссылки в CSS и HTML
не меняются. Для нестандартного пути выбери «Другой файл assets».

Перед заменой оригиналы сохраняются в `backups/<дата-время>/` с `manifest.json`.
«Восстановить копию» позволяет выбрать этот manifest. Если после замены файл
редактировали вручную, восстановление отменяется, чтобы не потерять новые правки.
Оригиналы в `.bak` остаются доступны для ручного восстановления.

Если исходник меняется после предварительного просмотра, применяется та версия,
которая была прочитана для просмотра. Для новой версии нажми «Показать замены» снова.
